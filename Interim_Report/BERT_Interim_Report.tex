\begin{abstract}
    The main aim of this project is to build a low-cost system that can test the Bit Error Ratio of a communication channel using a Pseudorandom Binary Sequence generator.
    So far, a transmitter has been successfully developed which generates a repeating PRBS-7 sequence with a length of 127 bits.
    The PRBS generator is controlled by a 10MHz clock signal where a bit is transferred at every rising edge, achieving a data rate of 10Mbps.
    This has been implemented on an FPGA.\@
\end{abstract}

\section{Project Description}
    Communication networks are continuously expanding in capacity and speed and being able to ensure signal integrity is paramount.
    The most common example of such a system is the internet, which uses undersea optical fibres for data transmission.
    Such networks have become a central component in the modern day world with applications in many important industries, such as telecommunications, cloud services, banking, healthcare and transportation.
    In accordance with these advancements, techniques to measure the performance of communication channels have evolved.
    Channels for digital communication as susceptible to incorrect data transmission arising due many possible factors such as noise or interference.
    A metric of performance for digital communication channels is the Bit Error Ratio (BER) which can be characterised via a Bit Error Rate Test (BERT).~\cite{SMJAlam2011}

    The BER of a communication channels is the proportion of bits in a data transmission which have an error.
    When received data has bit errors it requires either retransmission and/or extra processing from error correction algorithms.
    Hence, a high BER would have significant impacts on the channel's data rate capability.~\cite{SMJAlam2011}
    Being able to measure this is important in ensuring a channel can transmit data quickly and efficiently.
    Unfortunately, systems that can measure the BER can be expensive and would be designed for data rates in the Gb/s range.
    As a result acquiring such equipment could prove difficult and would be excessive since such high data rates aren't always required.~\cite{MJBasford2020}
    
    This project aims to construct a system that can accurately measure the BER of a Visible Light Communication (VLC) channel at data rates up to 10Mb/s, while keeping costs relatively low. Below are the main goals and objectives that need to be achieved by the end of this project. 

    \begin{enumerate}
        \item Make a Pseudo Random Binary Sequence (PRBS) generator
        \begin{itemize}
            \item To test the capability of the hardware choice
            \item To set a fixed word length in bits
            \item To generate a known sequence of bits that appear random
            \item To reach a bitrate of up to 10Mbps
        \end{itemize}

        \item Develop an Error detection algorithm
        \begin{itemize}
            \item To receive bitstream at up to 10Mb/s
            \item To generate the PRBS on receiver side
            \item To synchronise the PRBS with the received bit stream
            \item To calculate an error rate
        \end{itemize}
    \end{enumerate}

\section{Literature Review}
    Building a system to measure a channel's BER can be done via any programmable device such as Microcontrollers or Field Programmable Gate Arrays (FPGA).
    A sequence of known bits is required for testing a BER.\@
    One common method for generating one is the Pseudorandom Binary Sequence generator (PRBS).
    Such sequences are generated using a Linear Feedback Shift Register (LFSR) where two specific bits in the register are fed into an XOR or XNOR gate and fed back into the Least Significant Bit (LSB) of the register.~\cite{DRiccardi2011,MGeorge2007}
    Low cost BERTs have been developed using such methods.~\cite{MJBasford2020, SChatterjee2023, NMarda2014}
    Examples of these are discussed below.

    \subsection{Serial Communication BER Tester}
        An FPGA-based device was developed to test the BER of a serial communication channel.
        It uses a 31-bit LSFR to generate a PRBS which would have a length of \begin{math}
            2^{31} - 1
        \end{math} bits ({$\sim$}\begin{math}
            2.14 \times 10^9
        \end{math}).~\cite{MJBasford2020,DRiccardi2011}

        The system works by transmitting a PRBS to an external channel and receiving the bitstream on the same FPGA.\@
        The bits are generated, received and compared simultaneously.
        It is capable of testing data rates of up to 50Mbps and used the Anritsu MP8302A BERT for reference.~\cite{MJBasford2020}
        By transmitting and receiving on the same FPGA, having to synchronise bitstreams was not an issue.
        However, this is not good for simulating realistic transmission between two different devices.
    
    \subsection{VLC BER Tester}
        A PCB with logic circuits was designed to test a VLC channel.
        This is the same type of communication channel this project is meant for.
        In this case, the bit generator is simply a square wave rather than a PRBS.\@
        Effectively, the bit sequence being used to test the BERT is a sequence of alternating ones and zeros.~\cite{SChatterjee2023}

        Two separate PCBs are used for transmitting and receiving the bitstreams.
        This BERT can test for data rates up to 370kbps, which is significantly lower than this project's targetted data rates.
        As a result of using a periodic square wave, the issue of synchronising the transmitted and received bitstreams is simplified.
        This system has significantly smaller cost and complexity in comparison to FPGA equivalents.
        Unfortunately, in reality, bitstreams won't be sequential ones and zeros and would appear more random, meaning the displayed error ratio may not necessarily reflect real world conditions for data transmission.~\cite{SChatterjee2023}

    \subsection{Microcontroller-based BER}
        An STM32 Microcontroller combined with a Complex Programmable Logic Device (CPLD) was used to make a BER tester.
        A specific type of communication channel is not specified.
        This system uses pseudorandom patterns to test a channel.~\cite{NMarda2014}

        A single STM32 is used for both transmitting and receiving the bitstreams and tests the error ratio at 2.048Mbps.~\cite{NMarda2014}
        This data rate is similar to the data rate this project is targetting.
        Due to using only one device, this may not accurately simulate real world conditions.

    \subsection{Summary}
        Overall, both FPGAs and Microcontrollers seem as valid options in building a BER tester since they can both be programmed to transmit and receive a PRBS and compare bitstreams.
        In order to best simulate real world data transmission, two separate devices for transmitting and receiving would be ideal.
        While this may increase cost, relative to the price of BER equipment, it shouldn't be significant.~\cite{MJBasford2020,SChatterjee2023}
        A PRBS generator will be used to generate a bitstream that will be used for calculating the BER.\@

\section{Work Performed to-date}

    \subsection{Choice of Hardware}
        In this project, there is choice of hardware between using Microcontrollers or FPGAs.
        To determine which is suitable, the capabilities of a device of each were tested using a 10MHz clock signal. When a bitstream is synchronised to such a clock signal, each bit would be transferred on the rising edge of the clock. This would allow for data rate of 10Mbps.

        \subsubsection{MC}
            The board being tested here is the NUCLEO-F401RE board which has an STM32F401RET6 Microcontroller using the Serial Peripheral Interface (SPI) synchronous serial communication protocol.~\cite{NUCLEO2014,STM2014}
            It was programmed using STM32CUBEIDE.\@

            \begin{figure}[H]
                \centering
                \includegraphics[width=0.8\textwidth]{img/MC/10MHz_Clock.png}
                \caption{Oscilloscope capture of a 10MHz clock from the NUCLEO-F401RE}\label{fig:10MHz_MC}
            \end{figure}

            In \autoref{fig:10MHz_MC}, the clock signal is the correct frequency with an adequate peak-to-peak voltage.
            However, the signal appears to rise and fall exponentially rather than instantaneously like a typical square wave would.
            Different frequencies of clock signals can be used to test for this effect.

            \begin{figure}[H]
                \centering
                \includegraphics[width=0.8\textwidth]{img/MC/500kHz_Clock.png}
                \caption{Oscilloscope capture of a 500kHz clock from the NUCLEO-F401RE}\label{fig:500kHz_MC}
            \end{figure}

            In \autoref{fig:500kHz_MC}, it can be seen that the microcontroller produces a conventional square wave clock signal at 500kHz, suggesting that there is a frequency limitation in the measurement equipment. 

            \begin{figure}[H]
                \centering
                \includegraphics[width=0.8\textwidth]{img/MC/42MHz_Clock.png}
                \caption{Oscilloscope capture of a 42MHz clock from the NUCLEO-F401RE}\label{fig:42MHz_MC}
            \end{figure}

            In \autoref{fig:42MHz_MC}, the microcontroller is set to output a clock signal at its highest possible frequency of 42MHz.~\cite{NUCLEO2014,STM2014}
            The signal is almost triangular, but still holds a fundamental frequency of 42MHz.
            However, the peak-to-peak voltage (2.14V) is attenuated compared to that at 10MHz (3.36V) in \autoref{fig:10MHz_MC} and 500kHz (3.48V) in \autoref{fig:500kHz_MC}.

            The oscilloscope probe being used (RT-ZPO3) has a -3dB bandwidth of 10MHz which explains the distortion in the 10MHz and 42MHz clock signals.~\cite{R&S2019}
            This is because in the Fourier Series of a square wave, along with its fundamental frequency, there are other higher frequencies that allow the wave to be square.~\cite{JASvoboda2013}
            So even in a 10MHz square wave, which is exactly at the cut-off frequency, there are high frequency harmonics that exist which allow for the wave to be square.
            These frequencies are attenuated, giving the output in \autoref{fig:10MHz_MC}.
            But since the 10MHz frequency itself is within the bandwidth, there is little to no attenuation in the peak-to-peak voltage, like there is at 42MHz in \autoref{fig:42MHz_MC}.
            From testing at a lower frequency, it can be concluded that the hardware still produces are square wave at 10MHz with measurements being limited by the probe.

    \subsection{PRBS generator}
        For this project, a PRBS generator will be used to generate a bitstream for the BERT.\@
        At this point in time, a PRBS-7 generator has been made.
        A PRBS-7 would repeat every 127 bits and is represented by the following polynomial.~\cite{DRiccardi2011}
        \begin{equation}
            x^7 + x^6 + 1
        \end{equation}
        This polynomial isn't mathematical, it is a representation of the LFSR that would be used to generate a PRBS-7.
        The values of the powers represent which bits are used for the feedback.
        What this polynomial means is that the 7th and 6th bits of the register are inputs to an XOR gate where the output is fed into the Least Significant Bit (LSB) of the shift register.
        The Most Significant Bit (MSB) of the LFSR is transmitted to the communication channel.~\cite{DRiccardi2011,MGeorge2007}
        This can be implemented using D-Type Flip Flops in Quartus Prime.
        Typically, a much larger LSFR would be used to generate a PRBS in order to achieve a higher degree of randomness, as demonstrated in the Serial Communication BER Tester mentioned previously.~\cite{MJBasford2020}
        \subsubsection{Push Button Clock}

            For testing purposes, the clock will initially be tied to a push button on the DE0-Nano with the status of the LFSR tied to LEDs.
            Refer to \autoref{fig:FPGA_CLK_BTN} in the appendices for the Quartus Prime Lite logic diagram.
            The initial status of the LFSR is set to 7 ones. 
            The buttons on the FPGA are active low meaning they become logic level 0 when pressed and logic level one when released.
            The LSFR status varies when the button is released, not when pressed down.
            This means the PRBS generator is synchronised to the rising edge of the clock signal which is the expected behaviour.
            Once the button is pressed 127 times, the LSFR's status returns to the original state of 7 ones.
            Hence, PRBS generator is producing a repetitive bit sequence of length 127, which is also expected.

            When the initial seed is 7 ones, the expected repeating 127 bit sequence is the following.
            \begin{flushleft}
                \texttt{1111111000000100000110000101000111100100010110011101010011111010000111000100} \\
                \texttt{100110110101101111011000110100101110111001100101010}
            \end{flushleft}
            This can be compared to the output of the PRBS generator viewed on an oscilloscope.
